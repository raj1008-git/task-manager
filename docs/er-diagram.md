# Task Manager: ER Design (v1)

## Entity: Task

|                    TASK                     |
+---------------------------------------------+
| PK  id           BIGINT (auto-generated)    |
|     name         VARCHAR(100)  NOT NULL     |
|     description  VARCHAR(500)  NULL         |
|     status       VARCHAR(20)   NOT NULL     |
|                  DEFAULT 'TODO'             |
|                  CHECK IN (TODO,            |

## Relationships
- None in v1 (single entity).

## Future (v2, not built now)
USER 1 ---- N TASK
A `user_id` foreign key will be added to TASK when login is introduced.

## Design Decisions
- id is BIGINT generated by the database, so clients never choose it.
- status is VARCHAR with a CHECK constraint, not a PostgreSQL ENUM,
  because adding a new status later is a simple constraint change.
- created_at and updated_at are standard audit columns on every table.
- TIMESTAMPTZ stores time with timezone, which avoids timezone bugs.
- Database rules (NOT NULL, CHECK) back up the application validation,
  so bad data is blocked even if one layer has a bug.
